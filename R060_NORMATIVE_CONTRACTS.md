# R0.6.0 — Нормативная декомпозиция и заморозка исполняемых контрактов

**Дата:** 2026-11-06. **Статус:** `CONTRACTS_FROZEN_NOT_QUALIFIED`.

## 1. Источник истины и граница стадии

Два нормативных первоисточника, переданные пользователем:

- **СП 2.02.05-2026** «Пожарная безопасность зданий и сооружений», дата введения **2026-11-01**. Предисловие отменяет ТКП 45-2.02-110-2008. Предмет: расчёт огнестойкости и область применения (8.1–8.2), таблицы 2–12, приложения Ж, К, Л.
- **СП 5.03.01-2020** «Бетонные и железобетонные конструкции», предоставленное издание. Предмет: механика, общая деформационная модель (8.1.2), второй порядок (8.1.6), материалы (6.1, 6.2), конструирование (11.2–11.4).

Для самостоятельного формирования пожарных сочетаний эти два документа **не замыкают** нормативный набор: СП 2.02.05-2026, п. 8.2.17 отсылает к **СН 2.01.03-2019, §4.3**. Этот документ не входил в заданные пользователем два исходника и помечен `external_dependency / supplied=False`. До получения его полного текста разрешён только сценарий *внешние заранее вычисленные пожарные усилия с проверяемым происхождением*; это всё равно не позволяет заявить нормативное соответствие без реализации остальных процедур.

**Эта стадия НЕ реализует расчётную нормативную модель.** Она задаёт непересекающиеся роли, входы, область применимости, выходы, зависимости и обязательную квалификацию будущих алгоритмов. Существующие численные результаты K18 / R0.5.6 остаются диагностическими. Запрет на положительное R90 встроен в `prevent_normative_claim()`.

### Замороженные нормативные ветви

1. `general_member`: пожарные усилия → фактическое сечение/материалы → поле температур → температурные диаграммы → предельное N–Mx–My → второй порядок → приложение Л → огнестойкость. Вычислительный собственник каждой операции один.
2. `table_3_column`: проверка всех условий таблицы 3 → таблица огнестойкости → приложение Л → итог. **Не эквивалентна** общему численному расчёту и не применяется за границами §8.2.11.
3. `CRITICAL_ISOTHERM`: дополнительный `optional` контракт, который нельзя активировать без условий 8.2.21; не является частью общего расчёта по умолчанию.

Российский СП 468 — `comparison_only`; отменённый ТКП 2008 и Mathcad — `historical_replay`. Ни одна из трёх ветвей не может стать скрытой альтернативой нормам 2026/2020.

## 3. Параметрические ограничения, закреплённые кодом

- **Таблица 3:** для колонн по 8.2.11 должна соблюдаться расчётная длина ≤3 м, эксцентриситет ≤0,15h / ≤0,15b по соответствующим плоскостям, As/Ac ≤4%. Дополнительно необходимы подтверждённые η=Nfi/NRd, расстояние до оси арматуры, огневое сочетание и метод получения расчётной длины. Проверка численных ограничений работает, но без последней группы выдаёт только `INCOMPLETE`, не PASS.
- **Критическая изотерма:** при наличии *проверенного* тяжёлого бетона и указанного типа заполнителя: 500°C для силикатного или 600°C для карбонатного до C50/60; 460°C для C55/67–C60/75; 400°C для C70/85–C80/95. Любые иные классы/типы → `None`, а не 500°C по умолчанию. Это только **критерий материала**, отдельно проверяется геометрия / плоскость нагружения.
- **Ecm:** СП 5.03.01-2020, таблица 6.3 различает свойства по классу бетонной смеси, обработке и заполнителю; автоматическое `C30/37 -> 29 GPa` не является нормативным правилом.
- **Хрупкое разрушение:** по приложению Л αF=1,16×10^-2, β=0,6; оценка F≤4, потенциально опасный диапазон 4<F≤6, F>6; **приложение Л.6 предписывает защиту при F>4**. Следует различать вычисление индекса и меры защиты. В R0.6.0 нормативный расчёт F ещё не активирован.
- **Входные данные:** неизвестная влажность, вид заполнителя, свойства смеси, источники N/M, опорные условия и отдельные характеристики стали не заполняются по одному классу бетона или исходному примеру К18.

## 4. Исполняемая трассировка и контроль изменений

- Данные реестра содержатся в `rc_fire/normative/contracts.py` (замороженные `Source`, `Method`, `LegacyBlock`, `StructureCapability`).
- Версионированный JSON `R060_CONTRACT_MANIFEST.json`; стабильная SHA-256 подпись в `R060_CONTRACT_LOCK.json`.
- `validate_contract_registry()` проверяет уникальность методов, ссылки, отсутствие циклов, выбор ветви и отсутствие устаревшего/иностранного нормативного владельца.
- `audit_column()` формирует **компьютерно проверяемый** список блокирующих условий для каждой конструкции.
- `prevent_normative_claim()` запрещает выдавать нормативное заключение вне зависимости от совпадений с Mathcad или положительного диагностического результата.
- `validate_normative_result_provenance()` требует `source_id`, `source_clause`, `method_id`, `backend_version`, `input_sha256`, `applicability`, `qualification`, `units`; в R0.6.0 допустим только `CONTRACT_ONLY`.
- Не включать PDF стандартов или Mathcad пользователя в публичный GitHub; в репозитории сохраняются только криптографические отпечатки и ссылки на пункты.

## 5. Переход из Mathcad: сохранение всех 17 аудированных блоков

`LEGACY_INVENTORY` содержит 17 самостоятельных блоков расчётной цепочки К18, целевые методы и оставшиеся разрывы. Это **карта миграции**, а не утверждение, что 783 математические области уже преобразованы. Численная регрессия фиксированного К18 (ранее 44 показателя) должна остаться отдельным непрерывным тестом, не являющимся доказательством нормативной эквивалентности.

### Передача в R0.6.1

1. Материальный реестр `ConcreteMaterialSpec`, `ReinforcementSpec` с физическими данными, нормативными таблицами, граничными значениями и происхождением.
2. Разделение физического выбора материала и методики. У одного `owner` один производственный алгоритм и нормированная область; `legacy` и `comparison` только тестовые режимы.
3. Пример C30/37/600×600/R90 допускается к **диагностическому** расчёту, но не к нормативному выпуску без сведений о смеси, пожарной комбинации и опорах.
4. Независимые тесты табличных граничных значений, внеобластных условий, температурных коэффициентов, обеих осей, повторяемости и корректности размерностей.

## 6. Расширение на другие конструкции

`STRUCTURE_CAPABILITIES` уже содержит: прямоугольные колонны (diagnostic-only), круглые/кольцевые/центрифугированные колонны, балки (прямоугольные/тавровые/двутавровые), несущие стены, плиты (монолитные/ребристые/пустотные) и предварительно напряжённые элементы. Статус остальных **PLANNED**: никакое расширение UI не переводит их в `normative_supported` без отдельной квалификации механической и тепловой ветви.
